# Phase 5 Security & Compliance Skill Prompts

This directory holds the **`SKILL.md` templates** for the Phase 5 security skills referenced in [`../PROCESS.md`](../PROCESS.md) (Step 2.3 custom query authoring, Step 5.5 secrets incident response). They are templates, not active skills — Claude Code only auto-discovers folders under `.claude/skills/`.

Each skill encodes **one ordered procedure**. Unlike the [Phase 5 specialist subagents](../subagent-prompts/), which are invoked by name, **a skill auto-triggers from its description alone.** That makes the `description:` field the entire routing surface — read [Routing](#routing) before editing one, because both skills in this directory had triggers narrowed at build time for exactly that reason.

**Neither skill earns its keep by saving typing.** One enforces a proof that a query works in both directions; the other enforces an ordering people invert under pressure. Both would look redundant to a team that already did those things — and both exist because almost nobody does them at 2am.

## Files

| Folder | Procedure | Gate | Wraps |
|--------|-----------|------|-------|
| [`codeql-query-author/`](./codeql-query-author/SKILL.md) | Get the rule stated with a real anti-example and allowed-example from this repo, pick the language, read the pack and the workflow's query list, write the query with full metadata preferring dataflow over shape matching, commit both fixtures, run them and paste the real output, tighten the predicate rather than the severity if noisy, wire it into the pack and suite and prove the workflow picks it up, emit the PR note | [Gate 2 (SAST Quality Gate)](../QUALITY-GATES.md#gate-2-sast-quality-gate) — the custom-query checkbox, and the escalation clause that says a repeating false positive is fixed *at the query* | [`codeql-custom-query-generation`](../PROMPTS.md#codeql-custom-query-generation) |
| [`secret-leak-response/`](./secret-leak-response/SKILL.md) | Classify worst-case, rotate, verify the replacement in every environment, revoke and prove the old credential is dead, blast radius against real permissions, audit the full live window, notify by name, **only then** consider a history scrub, seed the post-mortem unposted | [Gate 5 (Secrets Hygiene)](../QUALITY-GATES.md#gate-5-secrets-hygiene) — sub-one-hour rotation MTTR, zero open incidents | [`secrets-incident-response`](../PROMPTS.md#secrets-incident-response) |

The **Wraps** column is this directory's purpose. Because shipped templates must stand alone in a consuming repo, each skill **inlines** its procedure with `{{PLACEHOLDERS}}` rather than linking back to `PROMPTS.md` — so the table above is the only record of where a procedure came from. Keep it current, or the round-trip is lost.

> **`secret-leak-response` is the one Phase 5 helper that is not sequenced.** Every other helper in the phase sits between two gates. This one fires the moment a credential leaks, on a fifteen-minute clock, and its value is entirely in the ordering it refuses to let you invert: **rotate, verify, revoke, prove dead — and only then scrub.** Scrubbing first feels like containment and does nothing whatsoever to a live credential, while deleting the record of how long it was exposed.

> **The false-positive loop in `codeql-query-author` is a gate clause, not a nicety.** Gate 2's escalation text says a pattern of repeating false positives is fixed by tightening the query and re-proving both fixtures — never by habitually dismissing the finding. Step 7 of the procedure is that clause, and its refusal case is the shortcut it exists to block: lowering `@problem.severity` turns a noisy query into a silent one and hides the change in a field nobody reviews.

## How to instantiate per repo

1. Copy the chosen **folder** into `.claude/skills/<skill-name>/` at the consuming repo root, preserving the folder name. **The folder name must equal the `name:` field** — Claude Code uses the folder name as the invocation slug, and a mismatch means the skill silently never loads. Use `cp -r`; globbing the Markdown files flattens the structure and produces zero working skills.
2. Replace the placeholders with the repo's values:
   - `{{CODEQL_LANGUAGES}}` — the languages CodeQL actually analyses in this repo, e.g. `javascript-typescript, python`. Must match what `.github/workflows/codeql.yml` builds; a query written for a language the workflow does not build produces no results **and no error** (codeql-query-author)
   - `{{SECRETS_MANAGER}}` — where the replacement credential is created and referenced from, e.g. `AWS Secrets Manager`. **Same value the Phase 6 infrastructure helpers use** (secret-leak-response)
   - `{{SECURITY_DOCS_DIR}}` — where security artefacts are committed, e.g. `docs/security/`. **Same value the Phase 5 subagents use** (secret-leak-response)
3. **`CodeQL` is written as a literal throughout, and so are `.github/codeql/`, `.github/codeql/test/` and `.github/workflows/codeql.yml`.** They are not fills. CodeQL is the prescribed SAST baseline, and the whole procedure — `qlpack.yml` and a `.qls` suite line, `@problem.severity` metadata, dataflow and taint-tracking classes over AST matching, the two-fixture run — is true of CodeQL and of nothing else. **A team on different tooling edits this template; it does not fill a value.** Parameterising the tool would ship a template that claims portability while enforcing one tool's rules, and the inconsistent fill would look correct on both sides. The same applies to the secrets skill's three prevention layers — pre-commit hook, platform push scan, AI-loop intercept — which are named as **layers rather than vendors**, precisely so the procedure survives a change of scanner.
4. **Neither skill needs an MCP server, and neither makes a tracker write.** `codeql-query-author` runs against the repository with the CodeQL CLI; `secret-leak-response` produces a runbook a human executes. That is one setup precondition fewer than most helpers in this framework — do not add one by wiring either skill to file its own findings.
5. Commit `.claude/skills/<skill-name>/SKILL.md` to the repo — skills at project scope are shared team infrastructure; treat edits as code changes requiring review.
6. **Verify. `/agents` does not list skills** — skills are a different surface and are verified differently. Run all four checks:
   - **Discovery.** Open a Claude Code session; the skill appears in the available-skills list under its slug. If not, the folder name and the `name:` field are out of alignment.
   - **Explicit invocation.** Type `/<skill-name>` with a representative input. The procedure should run top-to-bottom and stop where it hands over — for `secret-leak-response`, at the point a human must run the console steps.
   - **Auto-trigger, in messy language.** This is the check that matters, because the description is the whole routing surface:
     - `codeql-query-author` — *"every controller is supposed to call requireAuth first and someone keeps forgetting — can we make code scanning catch it"*
     - `secret-leak-response` — *"I think I just pasted our Stripe key into a prompt"*
   - **Refusal.** Drive each skill into its sharpest refusal and confirm it redirects rather than complies:
     - `codeql-query-author` — *"it's firing on forty files, just drop the severity to note"* and *"skip the fixtures, the query obviously works, we need this merged today"*
     - `secret-leak-response` — *"the key is in a public repo, rewrite the history first before anyone sees it"* and *"it's only the staging key, we'll rotate it next sprint"*
7. **Negative-routing check, once, after installing either.** Ask for ordinary work these skills must not claim — *"lint this file"*, *"add an ESLint rule for that"*, *"squash these commits"*, *"rebase onto main"*, *"rewrite the history to drop that big binary"*, *"set up secret scanning for the repo"* — and confirm neither loads. **The three git-history utterances are the ones to watch**, and they are the reason the secrets skill's history trigger names the credential; see [Routing](#routing).

## Routing

Skills auto-trigger; subagents do not. A skill whose trigger phrases reuse a verb an existing artifact already claims **wins that route by default and hijacks ordinary work.** Both skills here were narrowed at build time, and the two narrowings are worth reading before editing either description.

- **`codeql-query-author` must never carry a bare *"lint for this pattern"* or *"make sure nobody does this again"*.** Both were in the proposed trigger list and both were cut. *"Lint for this pattern"* fires on somebody wanting an ESLint rule and returns a CodeQL query — a plausible, committable, entirely wrong artefact. *"Make sure nobody does this again"* is worse: it is the exact sentence spoken at the end of a bug post-mortem, where the prevention action belongs to the bug procedure and its named owner. **Every surviving trigger names CodeQL, the query, or code scanning.** That qualifier is the whole boundary, exactly as the test-planning skill's triggers always carry "test plan".
- **`secret-leak-response` must never carry a bare *"rewrite git history"* or *"scrub the repo"*.** The proposed trigger *"do we need to rewrite git history"* is, unqualified, far more likely to be about squashing commits or dropping a large binary — and it would pull a fifteen-minute incident procedure into an ordinary git turn. The shipped trigger is *"do we need to scrub this key out of git history"*: **every history-related trigger names the credential.** Restoring the shorter phrasing re-opens the collision with the repo's conflict-resolution and rebase work.
- **Never add a bare development or review verb** to either skill — implement, fix, review the diff, refactor, open the PR. Those belong to the implementation and review specialists, and `codeql-query-author` sits one word away from *"fix this security finding"*, which is not its job.

| Skill | Owns | Explicitly does not own |
|---|---|---|
| `codeql-query-author` | One project-specific CodeQL query, its two fixtures, the proof it fires on one and not the other, its pack and suite wiring, the PR note | The vulnerability the pattern describes, GitHub's built-in query packs, any severity downgrade, deciding whether an existing finding is a true positive, adding a language to code scanning |
| `secret-leak-response` | One credential incident end to end: the rotation runbook, the revocation proof, the blast radius, the audit window, the notification list, the post-mortem seed | Executing the rotation, preventative scanner or secret-manager setup, any history rewrite before revocation is proven, the disclosure decision, the published post-mortem |

**Two lanes in this phase were reserved in advance from the other side, and that is a decision rather than luck.** The Phase 6 CI identity and secrets bring-up skill already excludes *"rotating a leaked credential during an incident"* by name, so `secret-leak-response` needed **no coordinated edit** — preventative setup and incident response were split before either existed. And the shipped Phase 2 design agents already route threat modelling away by work type, which closed the last outstanding coordinated edit for `threat-modeler` in the sibling directory. **A deliberately reserved lane reads identically to an oversight unless it is written down**, which is why both are recorded here and in [`docs/ROUTING.md`](../../../docs/ROUTING.md).

**Neither skill is scoped to a stage of the project.** A custom query is written the day somebody finds a pattern worth preventing, in month one or month nine; a credential leaks whenever it leaks. The cross-phase version of the ownership table lives in [`docs/ROUTING.md`](../../../docs/ROUTING.md); placeholder names that recur under other spellings elsewhere are reconciled in [`docs/PLACEHOLDERS.md`](../../../docs/PLACEHOLDERS.md).

One note worth preserving as the set grows. **Gate 4 — container and IaC review — has no skill here and will not get one.** It is the only gate in the phase with no detector behind it, and a skill that read a Dockerfile and returned a verdict would make an unscanned surface look gate-approved. An unbuilt helper is visible in this table by its absence; a confident wrong one is not.
